# Keep clean capture write-free

## Consumer effect

A maintainer can run capture routinely without accumulating evidence, status, or certification paperwork when no qualifying repeated responsibility is found.

## Authority

Conforms to `docs/principles/FOUNDATIONS.md` principles 12 and 15, `docs/principles/EVIDENCE-AND-DECISIONS.md` §5, `docs/principles/CONSUMER-CONTRACT.md` §2, accepted ADR 0001, accepted ADR 0020 item 6, and `docs/design/v0.1-scope-and-acceptance.md` §§2, 4, and 6.

## Narrow scope

- End a completed no-candidate run with the fixed statement owned by the capture skill package.
- Leave repository case history and the working tree unchanged.
- Verify the no-write result at the workflow boundary.

## Out of scope

- A clean-run receipt file, event, report, inventory, or certification record.
- A new event schema or durable clean-capture state.
- A compiled command whose only purpose is to print the statement.
- First-use inventory or denominator metrics.

## Acceptance

- A bounded clean capture emits the package's fixed terminal statement.
- No case event, report, receipt, draft, or other durable artifact is created.
- The repository working tree is byte-for-byte unchanged by the clean result.
- No command, schema, or compatibility promise is invented beyond implemented authority.
